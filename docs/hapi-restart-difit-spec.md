# ТЗ: интеграция HAPI с рестартом ревью difit

## Контекст

difit-хаб теперь умеет сам поднимать мёртвый ревью-сервер. Кнопка HAPI «Restart DIFIT»
сегодня просит агента перезапустить difit внутри сессии. С новой ручкой HAPI может
рестартовать ревью напрямую, без участия агента: достаточно открыть специальный URL.

## Что появилось в difit

### 1. Параметр `?restart=1` у viewer URL

    GET /reviews/<reviewId>/?restart=1

Поведение хаба:

1. Ревью-сервер жив. Хаб отвечает 302 на чистый URL `/reviews/<reviewId>/`, спавна нет.
2. Ревью-сервер мёртв, проверки прошли. Хаб спавнит новый detached-процесс
   `difit <args> --background` в папке репозитория и отдаёт HTML-страницу «Starting
   review server…». Страница поллит `GET /api/reviews` раз в 750 мс и делает
   `location.replace` на чистый URL, когда ревью стало `running`. Через ~45 секунд
   показывает ошибку и ссылки «открыть снапшот» и «попробовать снова».
3. Ревью-сервер мёртв, проверки не прошли. Параметр молча игнорируется, отдаётся
   сохранённый снапшот как обычно. Мёртвых ссылок нет.

Повторные клики безопасны: хаб не спавнит второй процесс для одного ревью в течение
15 секунд после первого спавна.

Повторный GET страницы после рефреша во время старта тоже безопасен с точностью до
гонки в первые 1-3 секунды: возможен второй спавн, хаб это гасит дедупом в своей
памяти (живёт до рестарта хаба).

### 2. Проверки перед спавном (guards)

Спавн происходит только если выполняется всё следующее:

- каталог `repositoryPath` из регистрации существует;
- для branch-ревью (`followsBranch: true`) текущая ветка репозитория совпадает с
  `branch` из регистрации. Иначе рестарт создал бы другое ревью с другим id:
  id это хеш от `repositoryId + branch + base + baseMode`;
- для revision-ревью оба рефа `baseRef` и `targetRef` резолвятся через
  `git revparse` в этом репозитории;
- stdin-ревью (`targetRef` или `baseRef` равен `stdin`) не рестартуют.

Если проверки не прошли, рестарт не выполняется и интерфейс ревью помечается
`restartable: false`.

### 3. Поле `restartable` и готовый viewer URL

    GET /api/reviews

Каждый элемент списка получил новое поле:

    restartable: boolean

Оно истинно, когда сервер не живёт и все guards прошли. `viewerUrl` при этом
содержит уже добавленный параметр: `/reviews/<reviewId>/?restart=1`.

Для HAPI это главный контракт: кнопка «Restart DIFIT» может просто открывать
`viewerUrl` из `/api/reviews` в браузере. Никаких дополнительных запросов не нужно.

### 4. Восстановление привязки к HAPI-сессии

Хаб прокидывает в заспавненный процесс `HAPI_SESSION_ID` из регистрации ревью.
Если в регистрации сессии нет, переменная окружения явно удаляется из окружения
процесса, чтобы не протекла сессия самого хаба.

Следствие: после рестарта wake при новых комментариях снова пинает ту же сессию
HAPI. Если сессия к тому моменту закрыта, wake тихо уходит в inbox, комментарии
не теряются. Перепривязки на другую сессию не происходит.

### 5. Как восстанавливаются аргументы CLI

Аргументы собираются из регистрации:

- branch-ревью: позиционный аргумент `targetRef` (`.`, `working`, `staged`), плюс
  `baseRef` вторым позиционным, если он не совпадает с подразумеваемым для этого
  target (`.` и `staged` подразумевают `HEAD`, `working` подразумевает `staged`);
- revision-ревью: `targetRef` и `baseRef` двумя позиционными;
- `--merge-base`, если `baseMode` равен `merge-base`;
- `--include-untracked` всегда, как это делает `scripts/deploy-local.sh`;
- `--background` добавляет спавнер: обёртка сама ставит `--keep-alive`,
  `--no-open` и ждёт handshake дочернего процесса.

Порт передаётся неявно: difit сам перепишет регистрацию (`~/.difit/reviews/<id>.json`)
новыми pid и портом, хаб читает файл заново при каждом проксировании.

### 6. Аутентификация и безопасность

- Ручка живёт за существующей auth хаба, как и весь просмотр ревью.
- Спавн возможен только по данным локального файла регистрации, наружу хаб не смотрит.
- Страница запуска отдаётся с CSP-nonce, инлайн-скрипт подписан nonce хаба.

## Что сделать на стороне HAPI

Минимальный вариант (рекомендуется):

1. В меню «More actions» действие «Restart DIFIT» для сессии с привязанным ревью
   открывает `viewerUrl` из `GET /api/reviews` (совпадение по `hapiSessionId` или
   по известному review id) в браузере пользователя. Параметр `?restart=1` уже внутри.
2. Если ревью живо, произойдёт обычный переход. Если мертво, хаб сам его поднимет.
3. Никакого промпта агенту для этого кейса больше не нужно. Промпт-вариант оставить
   для случаев, когда хаб недоступен или ревью `restartable: false`.

Опционально:

4. Показывать в HAPI состояние ревью по полям `running` и `restartable` из
   `/api/reviews`: «живое», «офлайн, можно поднять», «офлайн, рестарт невозможен».
5. После открытия рестарт-URL можно polling-ом ждать `running === true`, чтобы
   показать пользователю «ревью поднялось».

## Граничные случаи

- Репозиторий переехал или удалён: `restartable: false`, клик отдаёт снапшот.
- Ветка в репозитории переключена: то же самое, ревью помечается stale как раньше.
- Ревью на stdin-диффе: рестарт невозможен по определению.
- Хаб только что перезапустился: дедуп спавна пуст, но повторный клик всё равно
  не плодит процессы, пока ревью не начало отвечать на пробу порта.
