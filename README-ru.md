# Поддерживаемый форк Difit

Это поддерживаемый форк [yoshiko-pg/difit](https://github.com/yoshiko-pg/difit) для постоянных локальных ревью, которыми совместно пользуются браузер и coding agents. Он сохраняет GitHub-подобный просмотрщик diff из оригинального проекта и добавляет рабочее пространство для нескольких ревью, надёжную доставку обратной связи, плагин Codex и MCP-сервер.

Полное описание продукта, форматов diff, горячих клавиш и стандартных CLI-команд находится в [README оригинального проекта](https://github.com/yoshiko-pg/difit#readme). Здесь описаны только отличия и настройка форка.

## Чем отличается форк

| Область                | Поведение форка                                                                                | Что это даёт                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Hub ревью              | `difit hub` показывает ревью из разных репозиториев на одном адресе                            | Старые и текущие ревью легко найти без запоминания портов viewer-ов                                              |
| Переключатель ревью    | Запущенные ревью показаны как вкладки со счётчиками обновлений и своим состоянием интерфейса   | Между репозиториями можно переходить без перезагрузки страницы и потери вида, фильтра, прокрутки или черновика   |
| Ревью без агента       | Hub хранит последний отрисованный diff, комментарии и состояние ревью                          | Ревью остаётся доступным, когда viewer остановлен или checkout переключён на другую ветку                        |
| Живой diff             | Ревью working tree следит за tracked-изменениями и, при включении, за новыми untracked-файлами | Правки агента появляются автоматически без перезапуска viewer-а                                                  |
| Очередь агента         | Ответы и переходы `Assign Agent` или `Verify Fix` попадают в постоянную очередь                | Сообщения и поручения ждут агента нужного ревью и переживают перезапуски                                         |
| Идентичность ревью     | Репозиторий, ветка и база diff входят в идентичность ревью                                     | Комментарии из старой ветки не попадут в посторонний working tree                                                |
| Интеграция с агентом   | Один плагин Codex содержит скилл `difit` и stdio MCP-сервер                                    | Агент может открыть ревью, получить события, ответить, изменить комментарий и статус треда через одну интеграцию |
| Процесс ревью          | Из `Open` тред уходит в работу агента, во внешнюю правку или в `Closed`                        | Рабочие замечания доходят до `Ready` и `Resolved`, а вопрос можно закрыть, не выдавая его за исправленную ошибку |
| Работа с комментариями | Фильтры статусов, сворачивание ответов, просмотр полного файла и скрытые закрытые треды        | Большое обсуждение остаётся удобным и не разворачивает основной diff целиком                                     |
| GitLab                 | Живое MR-ревью сохраняет контекст merge request и добавляет ссылки на файл и строку            | Правки агента остаются видны, а из комментария можно перейти к нужному месту в GitLab                            |
| Безопасность           | Hub и viewer проверяют аутентификацию, host, origin, содержимое и Git-границы                  | Сам по себе loopback не считается границей безопасности                                                          |

Отдельный скилл `difit-review` намеренно удалён. Поддерживаемая версия находится в [`plugins/difit/skills/difit`](plugins/difit/skills/difit), а [`skills/difit`](skills/difit) оставлен как совместимая ссылка внутри репозитория.

## Установка форка

У репозитория нет отдельного npm-пакета. Следующие команды устанавливают оригинальный проект, а не этот форк:

```sh
npx difit
npm install --global difit
npx skills add yoshiko-pg/difit
```

Форк нужно устанавливать из ветки `custom`. Понадобятся Node.js 21 или новее, Git и pnpm 11.6.0.

```sh
git clone --branch custom --single-branch https://github.com/WarLikeLaux/difit.git
cd difit
corepack enable
pnpm install --frozen-lockfile
pnpm build
pnpm add --global .
difit --version
```

Обновление уже установленной копии:

```sh
git switch custom
git pull --ff-only origin custom
pnpm install --frozen-lockfile
pnpm build
pnpm add --global .
```

## Запуск hub

Браузерный dashboard рассчитан на локальный HTTPS reverse proxy. Сам difit не устанавливает proxy и не настраивает локальное доменное имя.

Если `https://difit.local` проксируется на `127.0.0.1:4965`, hub запускается так:

```sh
difit hub --host 127.0.0.1 --port 4965 --public-origin https://difit.local
```

Откройте настроенный HTTPS-адрес. При первом входе получите ключ браузера в доверенном терминале и введите его на странице входа:

```sh
difit auth key
```

После этого запустите ревью из нужного репозитория:

```sh
difit . --include-untracked --background
```

Ревью появится в hub. Пока viewer подключён, ревью working tree следит за своей исходной веткой и автоматически обновляется после изменений файлов. С `--include-untracked` учитываются и файлы, созданные уже после запуска. После переключения checkout на другую ветку сохранённое ревью становится read-only до повторного подключения viewer-а с той же идентичностью. Комментарии, оставленные в это время, сохраняются в очереди.

Удаление ревью из dashboard безвозвратно удаляет его snapshot, комментарии и ожидающие события.

## Рабочее пространство ревью

На страницах ревью за hub запущенные ревью показаны как вкладки. Переключение меняет URL и данные ревью без полной перезагрузки страницы. Выбранный основной экран, режим split или unified, фильтр кода, позиция прокрутки diff и незавершённые черновики комментариев хранятся отдельно для каждого ревью в пределах браузерной сессии. Первые четыре ревью видны сразу, остальные находятся в меню `More`.

Diff автоматически обновляется после изменений в подключённом working tree. Частые события объединяются, а обновления выполняются последовательно, поэтому серия записей приводит к последнему актуальному diff без параллельных перезагрузок. Если watcher отключился или разбор diff завершился ошибкой, остаётся ручная кнопка обновления.

Треды в `Closed` и `Resolved` по умолчанию скрыты из основного diff; их возвращает переключатель `Closed`. На экране Comments есть фильтры всех состояний, сворачивание тредов и скрытие ответов. `Show code` открывает изменённый файл целиком в модальном окне, подсвечивает строку комментария и прокручивает к ней; `Go to code` переводит к той же строке в основном diff.

Из `Open` процесс выбирает пользователь:

- правка нашим агентом: `Open` → `Assign Agent` → `Ready` → `Resolved`;
- правка внешним автором: `Open` → `Changes Requested` → `Verify Fix` → `Ready` → `Resolved`;
- изменение кода не требуется: `Open` → `Closed`.

Живое ревью GitLab MR нужно запускать из source-ветки merge request с target `.`: тогда последующие staged-, unstaged- и untracked-правки агента останутся видны.

```sh
difit . <target-branch> --include-untracked --gitlab-mr <merge-request-url> --background
```

## Плагин Codex и MCP

Плагин находится в [`plugins/difit`](plugins/difit). Его manifest устанавливает поддерживаемый скилл и запускает MCP-сервер командой:

```sh
difit mcp
```

Поэтому команда `difit` должна быть доступна в `PATH` MCP-сервера. Другие MCP-клиенты могут использовать готовую конфигурацию [`plugins/difit/.mcp.json`](plugins/difit/.mcp.json):

```json
{
  "mcpServers": {
    "difit": {
      "command": "difit",
      "args": ["mcp"]
    }
  }
}
```

Подробная инструкция по настройке, обновлению и подключению Difit (включая режим ревьюера `difit-reviewer`) к **Claude Code**, **Antigravity CLI** и **Cursor CLI** находится в [docs/agents-setup.md](docs/agents-setup.md).

MCP и CLI обращаются к одному аутентифицированному локальному API. Если плагин недоступен, CLI остаётся запасным способом работы.

В HAPI viewer нужно запускать с `--background` через shell текущей сессии агента, чтобы процесс унаследовал идентификатор сессии. Тогда новый комментарий сможет разбудить именно этого агента. Последующие действия выполняются через MCP; не следует запускать HAPI-привязанный viewer из долгоживущего MCP-процесса без контекста текущей сессии.

При повторном подключении или перезапуске существующего ревью каноническую команду нужно запускать без исходных аргументов `--comment`. Сохранённые треды восстановятся по идентичности ревью; повторный импорт стартовых комментариев без стабильных ID создаст дубликаты в `Open`.

## Дополнительные CLI-команды

Все стандартные targets оригинального difit продолжают работать. Форк добавляет следующие точки входа:

```sh
difit hub --host 127.0.0.1 --port 4965 --public-origin https://difit.local
difit mcp
difit review context --port <viewer-port>
difit auth key
difit comment events --port <viewer-port>
difit comment ack <through-seq> --port <viewer-port>
difit comment watch --port <viewer-port> --cursor-file <path>
difit comment accept <thread-id> --port <viewer-port>
difit comment request-changes <thread-id> --port <viewer-port>
difit comment verify <thread-id> --port <viewer-port>
difit comment ready <thread-id> --port <viewer-port>
difit comment reopen <thread-id> --port <viewer-port>
```

MCP охватывает тот же цикл работы: запуск и поиск ревью, чтение контекста и тредов, получение и подтверждение событий, создание и изменение сообщений, смена доступных агенту статусов.

## Граница безопасности

Для браузерного доступа используйте HTTPS hub. Прямые HTTP-порты viewer-ов по умолчанию слушают loopback, но не предлагают упрощённый вход через браузер. CLI и MCP аутентифицируются отдельно и не помещают учётные данные в URL.

Текст diff, имена файлов, комментарии, Markdown, SVG и Mermaid считаются недоверенными данными. Форк также отключает исполняемые Git-конвертеры для пассивного чтения и проверяет пути относительно репозитория перед доступом к файлам. Полная модель доверия и её ограничения описаны в [политике безопасности форка](.github/SECURITY.md).

## Разработка и обновление из upstream

Основная ветка форка — `custom`. Перед push нужно выполнить стандартные проверки:

```sh
pnpm check
pnpm test
pnpm build
```

Изменения upstream проверяются и вливаются в `custom`. Нельзя сбрасывать `custom` до `upstream/main`: так будут потеряны собственный процесс ревью и защитные изменения форка.

```sh
git remote add upstream https://github.com/yoshiko-pg/difit.git # один раз
git fetch upstream
git switch custom
git merge --no-ff upstream/main
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
```

Конфликты нужно разрешать с сохранением задокументированного поведения форка, особенно аутентификации, изоляции содержимого, постоянной идентичности ревью и CI-политики ветки `custom`. Dependency- и security-workflows сообщают о проблемах, но не обновляют пакеты автоматически.

История upstream-релизов находится в [CHANGELOG.md](CHANGELOG.md), а детали безопасности форка — в [`.github/SECURITY.md`](.github/SECURITY.md).
